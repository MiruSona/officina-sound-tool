### rfxgen 을 고른 이유

- `.rfx` 는 **104바이트 고정 바이너리** (헤더 8 + WaveParams 96 = int 2 + float 22). **포맷 분석이 끝났다.**
- Python `struct.pack` 으로 만들고 `rfxgen --input a.rfx --output a.wav` 로 굽는다. 두 단계뿐이다.
- 2016년 이후 포맷이 안 바뀌었고, 2026-08-13 에도 커밋이 있다. 공식 Windows x64 바이너리 제공.
- **pyfxr 은 실제로 못 쓴다** — 이 PC 가 Python 3.14 인데 wheel 이 3.13 까지만 있다.

### 장기 안전판

외부 실행파일 의존을 없애고 싶어지면 rfxgen 의 `GenerateWave`(약 310줄)를 Python 으로 포팅한다.
외부 의존성 없는 순수 C 이고 zlib 라이선스라 포팅이 허용된다. **지금 할 필요는 없다.**

## 3. 남은 일

- [ ] **사람이 SFX·BGM 을 들어 보고 프리셋을 손본다.** 코드는 「깨지지 않았나」만 보고 「좋은 소리인가」는 못 본다.
  들을 것을 다시 구우려면 `python -m soundtool sfx make Test/spec_example.json --out Out/sfx` (BGM 은 `bgm` · `spec_bgm_example.json`).
  **스크래치패드에 구운 것은 사라지니 `Out/` 처럼 안 지워지는 자리에 굽는다.**
- [ ] **스타일별 gain 또는 후처리 정규화.** 지금 스타일 사이 RMS 차가 **8 dB** 다 (−15.1 ~ −19.7 dBFS).
  SFX 처럼 구운 뒤 정규화하는 쪽이 단순할 수 있다.
- [ ] **장르별 SFX 프리셋 늘리기.** 게임 장르가 정해진 뒤. 어디에 더하나는 SFX 설계 3절 끝.
- [ ] **미니PC 실측** — rfxgen·fluidsynth 가 도는가. explosion 은 노이즈라 OS 가 다르면 파형이 달라질 수 있다.
  같은 seed 로 굽고 **SHA-256 을 대조**하면 5분에 확인된다.
- [ ] **키트 설치 스크립트** — `bin/` 의 셋(rfxgen·fluidsynth·sf2)을 받아 자리에 놓고 해시를 맞춰 보는 스크립트.
  지금은 손으로 놓는다 (`README.md` 설치).
- [ ] **Unity 쪽** — `manifest.json` 의 `tags` 로 소리를 찾는 에디터 스크립트와 임포트 설정. 이 툴 밖의 일이다.
- [ ] **GBNF 변환 실험** — `sfx/spec_schema.json` · `bgm/bgm.schema.json` 을 llama.cpp GBNF 로 바꿔
  LLM 이 스펙을 틀리게 못 쓰게 한다.
- [ ] **루프 메타데이터** — 지금은 WAV 를 정확히 잘라 두기만 한다. 루프 지점을 파일에 심는 것은 안 했다.
