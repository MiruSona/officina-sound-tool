# 사운드 툴 조사 (SFX / BGM)

> 대상 항목: `Docs/Todo/AI게임스튜디오.md` → "SFX와 BGM 만드는 툴"
> 조사일: 2026-08-19

## 추천안

**SFX용 : pyfxr (Python, BSD 라이선스)**
sfxr 스타일 파라미터(주파수·envelope·arpeggio 등)를 파이썬 코드로 그대로 지정해서 wav를 뽑아낸다. pip 설치, Windows wheel 제공, 상업적 사용 제약 없음. "AI가 파라미터를 정하고 코드가 소리를 만든다"는 목표에 가장 정확히 맞는다. 다만 최근 1년간 커밋이 없어 유지보수가 멈춘 상태라는 점은 리스크로 남는다. 유지보수가 걱정되면 2순위로 rfxgen(zlib 라이선스, 2025년 11월까지 활발히 관리됨, CLI 배치 변환 지원)을 함께 검토.

**BGM용 : MIDI 생성(mido/pretty_midi) + FluidSynth + 무료 사운드폰트(GeneralUser GS)**
파이썬 코드로 음표를 나열해 MIDI를 만들고, 커맨드라인 FluidSynth로 wav를 렌더링한다. 모든 구성 요소가 상업적 이용 가능하고 Windows에서 잘 돌며, 처음부터 끝까지 커맨드라인/스크립트로 자동화된다. Bandlab·Cakewalk·VCV Rack은 모두 "커맨드라인으로 처음부터 끝까지 자동 렌더"가 불가능해 제외했다. LMMS는 렌더 CLI는 있지만 프로젝트 파일 자체를 텍스트로 작성하는 표준 경로가 없어 후순위. 칩튠 느낌이 꼭 필요하면 사운드폰트를 8bit 계열로 바꾸는 정도로 대응하고, 진짜 트래커(.xm/.it) 자동 생성은 성숙한 라이브러리를 못 찾아 지금은 보류를 권한다.

---

## 판단 기준

- **자동화 가능 여부**: GUI 없이 커맨드라인/스크립트/API 만으로 끝까지 돌아가는가 (가장 중요)
- **라이선스**: 상업 게임에 결과물을 넣어도 문제없는가
- **유지보수 상태**: 최근에도 관리되고 있는가
- **Windows 지원**
- **우리 구조 적합성**: "AI가 지시 → 결정적 코드/신디사이저가 소리 생성" 구조에 맞는가

### SFX 결론 근거
- 목표가 "AI가 파라미터 결정 → 코드가 결정적으로 소리 생성"이므로, 파라미터를 코드에서 직접 넘길 수 있는 **pyfxr**이 구조상 제일 깔끔하다.
- ChipTone은 할일 문서의 참고 링크였지만, 오픈소스 저장소도 CLI도 확인되지 않아 자동화 후보에서 제외한다.
- pyfxr 유지보수가 멈춘 게 걸리면, 활발히 관리되는 **rfxgen**을 백업으로 검토하되 `.rfx` 파일 포맷을 직접 읽고 써야 완전 자동화가 되므로 추가 조사가 필요하다.

### 갈래별 정리

| 갈래 | 대표 도구 | 자동화 | 라이선스 | Windows | 비고 |
| --- | --- | --- | --- | --- | --- |
| **MIDI 생성 → 사운드폰트 렌더** | mido/pretty_midi (Python) + FluidSynth + GeneralUser GS(sf2) | 전 과정 CLI/스크립트 가능 | mido MIT / pretty_midi MIT / FluidSynth LGPL 2.1+ / GeneralUser GS 무제한(상업 포함) 무료 | 전부 지원, FluidSynth CLI: `fluidsynth -ni sf.sf2 in.mid -F out.wav -r 44100` | 가장 성숙하고 자동화 쉬움 |

| **텍스트 악보 언어 – LilyPond** | lilypond | 악보(출판물) 제작이 주 목적. MIDI 출력은 되지만 오디오 렌더링 자체는 별도 신스 필요 | GPL | O | 오디오화가 목적이 아니라서 부적합 |

### BGM 결론 근거
- **MIDI + FluidSynth + 무료 사운드폰트** 조합이 유일하게 "생성부터 렌더까지 전부 텍스트/코드+CLI"로 끊김 없이 자동화되고, 라이선스도 전부 깨끗하다. 1순위 추천.
- **Csound**, **SuperCollider(NRT)**는 진짜 "코드로 신스를 설계"하는 갈래라서 우리 목표에 철학적으로 가장 가깝다. 다만 학습 곡선이 있어서, MIDI+사운드폰트로 먼저 파이프라인을 돌려보고 표현력이 부족하면 2단계로 도입하는 걸 권한다.
- **트래커 포맷**은 "생성" 쪽 라이브러리가 없어서(재생기만 있음) 지금은 채택 보류. 나중에 진짜 칩튠 사운드가 필요해지면 별도로 더 조사해야 한다.
- 할일 문서에 있던 **Bandlab / Cakewalk / VCV Rack**은 셋 다 "커맨드라인만으로 작곡부터 렌더까지" 되는 근거를 찾지 못해 제외를 권한다. (LMMS는 렌더링 단계만 자동화 가능해서 후순위)

## 아직 확인 못한 것 / 사용자에게 물어볼 것

1. **pyfxr 유지보수 중단**을 감수하고 쓸지, 아니면 rfxgen의 `.rfx` 포맷을 분석해서 완전 자동화를 시도할지 확인 필요. (`.rfx` 포맷 스펙은 이번 조사에서 확인 못함 — 소스코드를 더 파봐야 함)
2. **원하는 BGM 스타일**이 칩튠(8bit)인지, 일반적인 배경음악(오케스트라/신스 계열)인지에 따라 추천이 달라진다. 칩튠을 강하게 원하면 트래커 포맷 쪽을 더 깊이 조사해야 한다.
3. **FluidSynth·사운드폰트를 로컬 Qwen(미니PC) 쪽에 설치할지, Claude Code 쪽에서만 쓸지** 실행 환경 배치를 아직 안 정함.
4. Csound/SuperCollider 같은 "코드형 신스"를 SFX 쪽에도 통합해서 SFX/BGM 엔진을 하나로 합칠지, 아니면 지금처럼 SFX(pyfxr)와 BGM(MIDI+FluidSynth)을 따로 둘지 결정 필요.
5. cfxr, jsfxr 포크들, mml2wav, rlib-MML 등 소규모 프로젝트의 정확한 라이선스 문구는 이번 조사에서 리포지토리 검색만 했고 LICENSE 파일 원문까지는 못 열어봤다 — 실제 채택 전에는 라이선스 파일을 직접 확인해야 한다.
6. abc notation(abc2midi) 경로를 MIDI 파이프라인의 "입력 문법" 대안으로 실제로 채택할지는 물어보지 않았다.
