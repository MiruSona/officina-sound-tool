# BGM 갈래 배포 조건 조사 (2026-08-25)

> 대상 : mido → FluidSynth → GeneralUser GS 로 BGM 을 굽는 갈래.
> 물음 : 이 툴을 **독립 키트**로 떼어 다른 게임에 설치해 쓸 때, 각 조각을 키트에 같이 넣어도 되는가.

## 1. 결론 표

| 항목 | 라이선스 | 키트 동봉 | 게임 배포 | 표기 의무 | 크기 |
| --- | --- | --- | --- | --- | --- |
| **GeneralUser GS 2.0.3** (사운드폰트) | GeneralUser GS License v2.0 (자체 허용 라이선스) | **가능** | **가능** (구운 wav 도, sf2 자체도) | 없음 | sf2 **30.8 MB** (32,319,396 바이트) |
| **FluidSynth 2.6.0** (신시사이저) | **LGPL 2.1 이상** | **가능** (exe·dll 를 그대로, 고치지 않고) | **가능** | LGPL 사본 동봉 + 출처 표기 권장 | win10-x64 zip **2.6 MB** |
| **MuseScore General 2.0** (대안 사운드폰트) | **MIT** | 가능 | 가능 | **있음** (저작권 문구 동봉 필수) | sf3 **38.0 MB** / sf2 **205.6 MB** |
| **mido 1.3.3** (Python MIDI 라이브러리) | **MIT** | 가능 (보통은 `requirements.txt` 로 충분) | 가능 | 저작권 문구 동봉 | wheel 순수 Python, 수백 KB |

**한 줄 결론 : 넷 다 그대로 써도 된다.** 지금 설계(mido → FluidSynth → GeneralUser GS)를 바꿀 이유가 없다.

### 다만 두 가지 주의

1. **GeneralUser GS 는 "자산 라이선스는 CC0·CC-BY·OGA-BY 만" 규칙의 예외로 둬야 한다.**
   자체 라이선스라 그 셋 중 어디에도 안 든다. 아래 3장에 판단 근거를 적었다.
2. **FluidSynth 는 고치지 말고 그대로 쓴다.** LGPL 은 "소스를 바꿨으면 바꾼 것도 LGPL 로 내놔라" 이므로,
   공식 zip 의 exe·dll 를 손대지 않고 **따로 떨어진 파일**로 두면 의무가 사실상 사라진다.
   우리는 명령줄로 부르기만 하므로 링크(linking) 문제 자체가 안 생긴다.

## 2. 근거

### 2-1. GeneralUser GS

- 공식 페이지 : <https://www.schristiancollins.com/generaluser>
- GitHub (문서·sf2 원본) : <https://github.com/mrbumpy409/GeneralUser-GS>
- 최신 판 : **2.0.3 (2026-02-22)**. 만든 사람 S. Christian Collins.
- 파일 : `GeneralUser-GS.sf2` = **32,319,396 바이트 (30.8 MB)**. 악기 261개, 드럼킷 13개.
- LICENSE 원문 (`documentation/LICENSE.txt`) 에서 그대로 옮김 :

  > You may use GeneralUser GS without restriction for your own music creation,
  > private or commercial. This SoundFont bank is provided to the community free of
  > charge. Please feel free to use it in your software projects, and to modify the
  > SoundFont bank or its packaging to suit your needs.

  (뜻 : 개인이든 상업이든 마음대로 써도 된다. 공짜로 푼 것이다. **네 소프트웨어 프로젝트에 넣어도 되고**,
  사운드폰트 자체나 그 포장을 고쳐도 된다.)

  > GeneralUser GS inherits the usage rights of the samples contained within, all of
  > which allow full use in music production, including the ability to make profit
  > from musical recordings created with GeneralUser GS.

  (뜻 : 안에 든 소리 샘플도 다 음악 제작에 마음껏 쓸 수 있고, 그것으로 만든 녹음물로 **돈을 벌어도 된다**.)

- **표기 의무는 라이선스 어디에도 없다.** 다만 이런 부탁이 하나 있다 :

  > If you plan to feature GeneralUser GS on your own website, please do not link
  > directly to my download files. Either link to my website, or provide your own
  > local copy instead.

  (뜻 : 남의 사이트에 올릴 때 **내 다운로드 파일로 직접 링크 걸지 말고**, 내 홈페이지를 링크하거나
  네 사본을 따로 두라. → **우리는 키트 안에 사본을 넣는 쪽이니 이 부탁에 딱 맞는다.**)

- **딱 하나 걸리는 대목** — 만든 사람이 스스로 밝힌 불확실성 :

  > Because GeneralUser GS originated as a personal project with no intention for
  > publication, I cannot be 100% sure where all of the samples originated, although
  > I do know that none of them came from commercially published SoundFont packages
  > or sample CDs.

  (뜻 : 원래 개인 취미로 시작한 것이라 **모든 샘플의 출처를 100% 확신하지는 못한다.** 다만 상업 판매용
  사운드폰트 묶음이나 샘플 CD 에서 가져온 것은 하나도 없다는 건 안다.)

  이어서 :

  > I have never received any complaint regarding sample ownership since I published
  > the original GeneralUser GS back in 2000, and as far as I am aware, neither have
  > any of the companies creating commercial software products using GeneralUser GS.

  (뜻 : 2000년에 처음 낸 뒤로 **소유권 항의를 한 번도 받은 적이 없고**, 이걸 쓴 상업 소프트웨어 회사들도
  마찬가지로 알기로는 없다.)

### 2-2. FluidSynth

- 공식 : <https://www.fluidsynth.org/> · GitHub : <https://github.com/FluidSynth/fluidsynth>
- 라이선스 : **LGPL 2.1 이상.** 저장소 `LICENSE` 첫 줄이 "GNU LESSER GENERAL PUBLIC LICENSE Version 2.1, February 1999".
- 공식 위키의 라이선스 FAQ (`doc/wiki/LicensingFAQ.md`) :

  > **Q: Can I include FluidSynth in my closed-source commercial project?**
  > A: That depends. FluidSynth is licensed under LGPL, which (unlike GPL) makes it
  > possible to dynamically link with code under other licenses. …
  > * The end user of your project must be able to change/upgrade the FluidSynth part
  >   of the project independently of you.
  > * All changes to FluidSynth itself (i e the so/dll) must be made available under
  >   the terms of the LGPL.

  (뜻 : 소스 안 여는 상업 프로젝트에 넣어도 된다. 단 ① 사용자가 FluidSynth 부분만 따로 갈아끼울 수 있어야
  하고 ② FluidSynth 자체를 고쳤으면 그 고친 것은 LGPL 로 공개해야 한다.
  → **우리는 exe 를 명령줄로 부르기만 하니 ①②가 저절로 지켜진다.**)

  > **Q: Can I use FluidSynth to make commercial music?**
  > A: Yes, definitely! FluidSynth can not claim anything when it comes to the sound
  > output. Just make sure to check the license conditions on the **input** …

  (뜻 : 구워 나온 소리에 대해 FluidSynth 는 아무 권리도 주장하지 않는다. **넣는 것**(MIDI·사운드폰트)의
  라이선스만 챙기면 된다. → 우리가 굽는 wav 는 GeneralUser GS 조건만 보면 된다.)

#### Windows 바이너리 받는 곳

| 길 | 상태 | 비고 |
| --- | --- | --- |
| **공식 GitHub release zip** | **이걸 쓴다** | `fluidsynth-v2.6.0-win10-x64-cpp11.zip` — 2,722,370 바이트 (2.6 MB), 2026-08-11 낸 것 |
| choco | 있지만 `2.4.7 [Approved] - **Possibly broken**` 이라고 뜬다 | 실제로 `choco search fluidsynth` 를 돌려 확인 |
| winget | **없다** | `winget search fluidsynth` → "입력 조건과 일치하는 패키지를 찾을 수 없습니다" |

받는 곳 : <https://github.com/FluidSynth/fluidsynth/releases>
zip 을 풀어 폴더 하나(예: 키트 안 `bin/fluidsynth/`)에 두고 exe 경로를 코드에 적는 방식이 제일 낫다.
PATH 를 건드리지 않아도 되고, 키트 규칙("툴 폴더는 그 자체로 완결")에도 맞는다.

#### MIDI → WAV 굽는 명령 꼴

man 페이지(`doc/fluidsynth.1`)의 SYNOPSIS 는 `fluidsynth [options] [SoundFonts] [midifiles]` 다.
쓸 옵션은 이렇다.

| 옵션 | 뜻 |
| --- | --- |
| `-n, --no-midi-in` | MIDI 입력 장치를 안 연다 (배치로 구울 때 필수) |
| `-i, --no-shell` | 대화형 셸을 안 띄운다 (안 주면 명령이 안 끝나고 멈춰 있는다) |
| `-F, --fast-render=[file]` | MIDI 를 실시간이 아니라 **최대 속도로 파일에 굽는다** |
| `-T, --audio-file-type` | 출력 형식 (`wav` 등). `-T help` 로 목록 |
| `-O, --audio-file-format` | 샘플 형식 (16bit 등) |
| `-r, --sample-rate` | 샘플레이트 (예 44100) |
| `-g, --gain` | 전체 음량. 0 < gain < 10, **기본값 0.2** (기본이 작아서 대개 올려야 한다) |
| `-R 0` / `-C 0` | 리버브 / 코러스 끄기 |
| `-q, --quiet` | 잡소리 출력 안 함 |

기본 꼴 :

```
fluidsynth -ni -F out.wav GeneralUser-GS.sf2 in.mid
```

실제로 쓸 꼴 (게임용, 44.1kHz · 음량 올림) :

```
fluidsynth -ni -q -T wav -r 44100 -g 0.8 -F out.wav GeneralUser-GS.sf2 in.mid
```

> **아직 안 돌려봤다.** FluidSynth 를 설치하지 않았으므로 위 명령은 man 페이지를 읽고 조립한 것이다.
> 설치한 뒤 첫 시험에서 ① 파일이 생기는지 ② 음량이 안 깨지는지(클리핑) 두 개를 본다.

### 2-3. 대안 사운드폰트 — MuseScore General

GeneralUser GS 가 못 쓰게 되거나 소리가 안 맞으면 이걸 쓴다.

- 받는 곳 : <https://ftp.osuosl.org/pub/musescore/soundfont/MuseScore_General/>
- 라이선스 : **MIT.** 라이선스 문서 : `MuseScore_General_License.md` (위 폴더 안)
- 크기 (HTTP 헤더로 직접 확인) : `MuseScore_General.sf3` **39,900,972 바이트 (38.0 MB)** ·
  `MuseScore_General.sf2` **215,614,036 바이트 (205.6 MB)**
- **표기 의무가 있다.** MIT 이므로 저작권 문구를 그대로 실어야 한다 :
  Frank Wen (FluidR3, 2000–2002 · 2008), Michael Cowgill (모노 변환 2014–17),
  S. Christian Collins (MuseScore 판 2018–19), Ethan Winer, Michael Schorsch.
- 재미있는 점 : **만든 사람이 GeneralUser GS 와 같은 S. Christian Collins** 다 (FluidR3 를 손본 것).
  소리 성향이 비슷해서 갈아끼워도 곡이 크게 안 어색할 가능성이 높다.
- 주의 : `.sf3` 는 압축본이라 FluidSynth 가 libsndfile(ogg/vorbis) 을 품고 빌드돼야 읽는다.
  **공식 Windows zip 이 sf3 를 읽는지는 확인 못 했다.** 안 되면 205 MB 짜리 sf2 를 써야 하는데 너무 크다.
  → **그래서 기본은 GeneralUser GS(30.8 MB, sf2) 가 맞다.**

### 2-4. mido

- PyPI : <https://pypi.org/project/mido/> (JSON API 로 확인)
- 최신 판 **1.3.3**, 라이선스 **MIT**
- `requires_python` = `~=3.7` → **3.7 이상 4.0 미만.** 그러니 **Python 3.14 에서 설치된다.**
- wheel 이름이 `mido-1.3.3-py3-none-any.whl` → **순수 Python.** C 컴파일이 없으니
  rfxgen 조사 때 pyfxr 이 걸렸던 "3.13 까지만 wheel" 문제가 여기서는 안 생긴다.
- 의존성은 `packaging` 하나뿐 (이것도 순수 Python).
  MIDI 포트(실시간 연주) 쪽 의존성 `python-rtmidi` 는 **extra 라서 안 깔린다.**
  우리는 파일만 쓰고 읽으므로 필요 없다.
- **pip install 은 하지 않았다.** PyPI 메타데이터만 봤다.

## 3. "자산은 CC0·CC-BY·OGA-BY 만" 규칙과의 관계

**판단 : 사운드폰트는 이 규칙의 예외로 둔다.** 이유는 셋이다.

1. **사운드폰트는 게임에 들어가는 자산이 아니라 자산을 만드는 도구다.**
   게임에 실려 나가는 것은 구워진 `.wav`(또는 `.ogg`) 이지 `.sf2` 가 아니다.
   그림으로 치면 붓이지 그림이 아니다. 규칙은 **결과물 자산**을 겨눈 것이므로 결이 다르다.
2. **CC0/CC-BY 를 단 GM 사운드폰트가 사실상 없다.** 널리 쓰이는 자유 GM 사운드폰트는
   GeneralUser GS(자체 라이선스), FluidR3 / MuseScore General(MIT), TimGM6mb(GPL) 정도이고
   CC0 짜리는 쓸 만한 게 없다. **규칙을 그대로 들이대면 BGM 갈래 자체가 성립을 안 한다.**
3. **두 후보 다 상업 사용·재배포·표기 없음(또는 문구 한 장)이라 CC0/MIT 수준으로 느슨하다.**
   규칙이 막으려던 것(나중에 라이선스 때문에 자산을 다 갈아엎는 일)은 여기서 안 일어난다.

다만 GeneralUser GS 의 **샘플 출처 불확실성**은 기록으로 남겨 둔다.
만든 사람이 26년째 항의를 받은 적 없다고 밝혔고 상업 제품 다수가 쓰고 있어 실질 위험은 낮다고 본다.
그래도 마음에 걸리면 **MuseScore General(MIT)** 로 갈아타면 된다 — 같은 사람이 만들었고 명령줄만 바꾸면 된다.

> 사람이 정해 줄 것 : 위 예외를 받아들일지, 아니면 처음부터 MIT 인 MuseScore General 을 기본으로 할지.
> (기본을 MuseScore General 로 하면 크기가 30.8 MB → 38 MB 로 늘고 sf3 읽기 확인이 하나 더 붙는다.)

## 4. 키트에 넣을 것 정리

떼어 낼 독립 저장소에 이렇게 담으면 된다.

| 넣을 것 | 자리 | 비고 |
| --- | --- | --- |
| `GeneralUser-GS.sf2` (30.8 MB) | `assets/soundfont/` | LICENSE.txt 도 같이 |
| FluidSynth win10-x64 zip 을 푼 것 (2.6 MB) | `bin/fluidsynth/` | LGPL 사본 같이. **고치지 않는다** |
| `THIRD-PARTY.md` | 저장소 뿌리 | 위 표 네 줄을 그대로 옮겨 적는다 |

> 30 MB 짜리 바이너리를 git 에 넣는 게 부담이면 **받는 스크립트**로 대신할 수도 있다.
> 다만 GeneralUser GS 는 "내 다운로드 파일로 직접 링크 걸지 말라"는 부탁이 있으니,
> 자동으로 긁어오는 스크립트보다 **사본을 넣는 쪽**이 부탁에 더 맞는다.

## 5. 확인한 것 · 확인 못 한 것

**직접 읽고 확인한 것**

- GeneralUser GS `documentation/LICENSE.txt` 전문 (GitHub API 로 원문 받아 읽음) — 판 2.0.3
- GeneralUser GS `documentation/CHANGELOG.md` 머리 — 2.0.3 은 2026-02-22
- `GeneralUser-GS.sf2` 크기 32,319,396 바이트 (GitHub API contents)
- FluidSynth `LICENSE` 첫 줄 = LGPL 2.1
- FluidSynth `doc/wiki/LicensingFAQ.md` · `doc/wiki/Download.md` 전문
- FluidSynth `doc/fluidsynth.1` (man 페이지) 의 SYNOPSIS 와 옵션 목록
- FluidSynth 최신 release v2.6.0 (2026-08-11) 과 win10-x64 zip 크기
- `winget search fluidsynth` (없음) · `choco search fluidsynth` (2.4.7, possibly broken) 실제 실행
- mido PyPI JSON 메타데이터 (판 1.3.3, MIT, `~=3.7`, `py3-none-any`)
- MuseScore General sf3/sf2 파일 크기 (HTTP HEAD)

**확인 못 한 것**

- FluidSynth 를 **실제로 돌려서** wav 를 구워 보지는 않았다 (설치 금지라서). 명령 꼴은 문서 기반.
- 공식 Windows zip 이 `.sf3` 압축 사운드폰트를 읽는지.
- `schristiancollins.com` 본문 페이지는 스크립트로 그려져서 못 읽었다. 대신 같은 사람이 관리하는
  GitHub 저장소의 LICENSE 원문으로 대체했다 (내용은 같은 v2.0 라이선스).
- 소리 품질 비교 (GeneralUser GS vs MuseScore General) — 굽고 들어봐야 안다.
