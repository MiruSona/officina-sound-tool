# `.rfx` 엔디안 실물 확인

> 확인일 : 2026-08-25
> 대상 : `Research/2026-08-20-SFX엔진재조사.md` 의 "확인 못한 것 — 엔디안"
> 확인 방법 : 실제로 파일을 만들어 rfxgen 으로 구워 봤다 (`Test/rfx_probe.py`)

---

## 결론

**`.rfx` 는 리틀 엔디안이다. 빅 엔디안은 rfxgen 이 거부한다.**

Python 에서는 이 한 줄이면 된다.

```python
struct.pack("<4sHH2i22f", b"rFX ", 200, 96, *params)  # 104바이트
```

근거는 두 가지다.

1. **소스 코드** — `rfxgen.h` 의 `SaveWaveParams()` 는 `WaveParams` 구조체를 `fwrite` 로 통째로 쏟아 붓고,
   `LoadWaveParams()` 는 `fread` 로 통째로 읽는다. 변환이 없으니 **파일 엔디안 = 그 PC 엔디안**이고,
   공식 바이너리가 나오는 x64/ARM64 데스크톱은 전부 리틀 엔디안이다.
2. **실물 시험** — 아래 대조 결과.

## 실물 시험 결과

`python SoundTool/Test/rfx_probe.py` 실제 출력 :

```
기대 프레임 수 = 35000 (0.7937초)

[little endian] 104바이트, 헤더=72 46 58 20 c8 00 60 00
  rfxgen exit=0
  WAV = {'channels': 1, 'bits': 16, 'rate': 44100, 'frames': 35003, 'seconds': 0.793718820861678}

[big endian] 104바이트, 헤더=72 46 58 20 00 c8 00 60
  rfxgen exit=0
  | [...\probe_big.rfx] rFX file version not supported (51200)
  WAV = {'channels': 1, 'bits': 16, 'rate': 44100, 'frames': 3, 'seconds': 6.802721088435374e-05}

리틀엔디안 되읽기: b'rFX ' 200 96
  params: {'randSeed': 12345, 'attackTimeValue': 0.1, 'sustainTimeValue': 0.5,
           'decayTimeValue': 0.3, 'startFrequencyValue': 0.5, 'lpfCutoffValue': 1.0}
```

파형 진폭도 따로 봤다 : `little frames 35003 peak 6565` / `big frames 3 peak 0`.

읽는 법 :

- **리틀 엔디안** — 어택 0.1 · 서스테인 0.5 · 디케이 0.3 을 넣었더니 나온 WAV 가 **35003 프레임**.
  `rfxgen.h` 의 엔벨로프 식(`t*t*100000`)으로 계산한 값 35000 과 3 프레임 차이다.
  **넣은 숫자가 소리 길이로 그대로 나왔다** = 필드를 제대로 해석했다는 뜻이다.
- **빅 엔디안** — 시그니처 `rFX ` 는 char 배열이라 그대로지만 버전 200(`0x00C8`)이 뒤집혀
  **51200(`0xC800`)** 으로 읽히고, rfxgen 이 `rFX file version not supported` 를 찍고 파라미터를 **버린다**.
  종료 코드는 여전히 0 이고 **무음 3프레임짜리 WAV 가 조용히 나온다.**
  → **exit code 로는 실패를 못 잡는다.** 나중에 SFX 툴을 짤 때는 나온 WAV 의 프레임 수를 꼭 확인해야 한다.

빅 엔디안이 "이상한 소리"가 아니라 "무음"인 이유는, 헤더 검증에서 걸려 파라미터 96바이트를 아예 안 읽고
`WaveParams params = { 0 }` 상태로 생성에 들어가기 때문이다. 길이가 전부 0 이라 소리가 없다.

## 파일 구조

총 **104바이트** 고정. 헤더 8 + `WaveParams` 96. 전부 4바이트 정렬이라 패딩 없음.

### 헤더 (8바이트)

| 오프셋 | 크기 | 형 | 이름 | 값 | 실제 바이트 |
| --- | --- | --- | --- | --- | --- |
| 0 | 4 | char[4] | signature | `"rFX "` | `72 46 58 20` |
| 4 | 2 | uint16 | version | `200` | `c8 00` |
| 6 | 2 | uint16 | dataLength | `96` | `60 00` |

rfxgen 이 검사하는 것은 이 셋뿐이다. 셋 다 맞아야 파라미터를 읽는다.

### WaveParams (96바이트, 오프셋 8부터)

기본값은 `rfxgen.h` 의 `ResetWaveParams()` 값이다.

| 오프셋 | 형 | 이름 | 기본값 |
| --- | --- | --- | --- |
| 8 | int32 | `randSeed` | 무작위 (1~0xFFFE) |
| 12 | int32 | `waveTypeValue` | 0 (사각) |
| 16 | float | `attackTimeValue` | 0.0 |
| 20 | float | `sustainTimeValue` | 0.3 |
| 24 | float | `sustainPunchValue` | 0.0 |
| 28 | float | `decayTimeValue` | 0.4 |
| 32 | float | `startFrequencyValue` | 0.3 |
| 36 | float | `minFrequencyValue` | 0.0 |
| 40 | float | `slideValue` | 0.0 |
| 44 | float | `deltaSlideValue` | 0.0 |
| 48 | float | `vibratoDepthValue` | 0.0 |
| 52 | float | `vibratoSpeedValue` | 0.0 |
| 56 | float | `changeAmountValue` | 0.0 |
| 60 | float | `changeSpeedValue` | 0.0 |
| 64 | float | `squareDutyValue` | 0.0 |
| 68 | float | `dutySweepValue` | 0.0 |
| 72 | float | `repeatSpeedValue` | 0.0 |
| 76 | float | `phaserOffsetValue` | 0.0 |
| 80 | float | `phaserSweepValue` | 0.0 |
| 84 | float | `lpfCutoffValue` | **1.0** |
| 88 | float | `lpfCutoffSweepValue` | 0.0 |
| 92 | float | `lpfResonanceValue` | 0.0 |
| 96 | float | `hpfCutoffValue` | 0.0 |
| 100 | float | `hpfCutoffSweepValue` | 0.0 |

`lpfCutoffValue` 만 기본값이 1.0 이다. **0 으로 채운 파라미터를 넘기면 로우패스가 완전히 닫혀 소리가 안 난다.**

소리 길이(프레임) = `(attack² + sustain² + decay²) × 100000`, 샘플레이트 44100 고정.
(`rfxgen.h` `GenerateWave()` 346~348줄)

## rfxgen 버전과 WAV 출력 형식

| 항목 | 값 |
| --- | --- |
| 버전 | **rFXGen v5.0** (2025-11-13 릴리스) |
| 받은 곳 | `https://github.com/raysan5/rfxgen/releases/download/5.0/rfxgen_v5.0_win_x64.zip` |
| 둔 곳 | `SoundTool/bin/rfxgen.exe` (+ `LICENSE`, `README.md`) — `SoundTool/.gitignore` 로 git 제외 |
| 라이선스 | zlib/libpng |
| 내부 생성 형식 | 44100 Hz · 32bit float · 모노 (`RFXGEN_GEN_*` 상수, 고정) |
| **WAV 기본 출력** | **44100 Hz · 16bit · 모노** (실측) |
| 형식 바꾸기 | `--format <22050\|44100>,<8\|16\|32>,<1\|2>` |

`--help` 예시 문구에는 기본이 "44100 Hz, 32 bit, Mono" 라고 적혀 있지만 **실제로는 16bit 로 나온다.**
도움말 문구가 틀렸다. 형식이 중요하면 `--format` 을 명시하는 게 안전하다.
