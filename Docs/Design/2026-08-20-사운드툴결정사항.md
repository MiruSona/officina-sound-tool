# 사운드 툴 결정사항

SFX·BGM 툴에 대해 2026-08-20 까지 정해진 것과 아직 안 정해진 것을 모은 문서다. 설계의 입력값으로 쓴다.

> 원래 `2026-08-20-그림사운드툴결정사항.md` 한 문서였다. 툴을 폴더로 가르면서 사운드 쪽만 떼어 왔다.
> **아래 "같이 쓰는 결정" 은 그림 툴과 같은 결정을 공유하므로 양쪽에 다 적어 둔다.**

조사 근거는 `Docs/Research/` 의 문서들에 있다.

## 같이 쓰는 결정 (그림 툴과 공유)

| 항목 | 결정 |
| --- | --- |
| AI 의 역할 | **AI 는 짧은 JSON 만 뱉고, 실제 결과물은 코드가 만든다** |
| 가장 큰 목적 | 클라우드 AI(Claude) **토큰 절약** |
| 툴 형태 | **CLI + JSON 입력** |
| 무거운 반복 작업 | 미니PC 에서 돌린다 |
| 로컬 LLM | **새로 추가할 모델 0개.** 이미 쓸 Qwen + llama.cpp GBNF 로 JSON 스키마를 강제한다 |
| 검수 | **코드로 한다.** 소리는 librosa+FFT, 그림은 numpy/Pillow. VLM 은 안 쓴다 |
| 에셋 고르기 | JSON 태그 검색 |

## 정해진 것 — 사운드 툴

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| SFX 엔진 | **rfxgen** (zlib) | pyfxr 에서 바꿈 |
| BGM 엔진 | mido → FluidSynth → GeneralUser GS | 전부 명령줄로 이어진다 |
| SFX·BGM 통합 | **안 함. 따로 간다** | Unity 에서도 따로 다룬다 |
| 악보 문법 | abc notation 안 씀 | 사람이 악보를 쓸 일이 없다 |

`.rfx` 는 **104바이트 고정 바이너리**(헤더 8 + WaveParams 96 = int 2개 + float 22개)로 포맷 분석이 끝났다.
Python `struct.pack` 으로 만들고 `rfxgen --input a.rfx --output a.wav` 로 굽는다. 2016년 이후 포맷이 안 바뀌었다.

**이 PC 는 Python 3.14 다.** pyfxr 은 wheel 이 3.13 까지만 있어 실제로 못 쓴다. rfxgen 으로 바꾼 판단이 맞았다.

## 지금 바로 할 수 있다

**사운드 툴은 그림과 아무 상관이 없다.** 그림체·시점 같은 미정 사항을 안 기다려도 되고,
조사도 끝나 있어 바로 설계·작업에 들어갈 수 있다.
